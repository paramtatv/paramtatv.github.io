Seeing exactly: Darśana and the road to Svarūpa

Darśana (दर्शन) means seeing. For us it also names a promise: what a camera's sensor recorded is what you get back, every sample, every time, on every machine.

This post covers what Darśana is today and where Svarūpa, the next step, is taking it.

A codec that is its own specification

Most image formats are defined by a prose document, and the decoders that follow it are written separately. Darśana works the other way round. Its normative decoder is a program, written in Sassembly, our Sanskrit-native RISC-V assembly language. That program is the specification. If you want to know what a Darśana file means, run the decoder.

The decoder is small. As a complete RISC-V image, code and data together, it measures 27,272 octets. The written normative description that accompanies it is checked mechanically, and all 1,990 of its 1,990 checks pass.

The everyday tool runs alongside it. darsan is a command-line program in plain C99 with no dependencies. It is a twin of the normative decoder, and the two are held to agreement byte for byte, so speed never changes the answer.

Built from exact integer parts

Every stage of the codec is integer arithmetic, and every stage is proven against an independent reference:

  • The transform is the H.264 4×4 integer inverse transform. It passes all 16 of its reference vectors.
  • The entropy coder is rANS. It passes round-trip and desynchronisation tests, using a fixture produced by a separately written encoder.
  • The test vectors are themselves tested. We deliberately break the implementation (a logical shift where an arithmetic one belongs, a dropped rounding step, a transposed matrix) and check that the vectors catch every mutant. They catch all of them.
  • Integrity checks use SHA-256, verified against the FIPS 180-4 test vectors, and a CRC on every part of the file.

One answer on three architectures

Exactness only means something if it holds everywhere. We run the same decoding work on three very different machines, x86-64, 64-bit RISC-V and WebAssembly (wasm32), and fold the result into one checksum. All three report the same value: 1267710892.

A real camera frame, sample for sample

The Sassembly encoder writes a full 12.13-megapixel frame. Its output is byte-identical to the reference encoder's, and the Sassembly decoder turns it back into the original exactly. The encoder exists in three languages (Sassembly, Python and C), and all three produce identical bytes.

With the C tool, a public-domain (CC0) iPhone 6s Plus DNG from raw.pixls.us, 4032 × 3008 sensor samples, becomes 8,727,526 octets at 5.757 bits per sample, and every sample is checked on the way back. The encoder decodes what it has just written and confirms the match before it reports success. Darśana reads DNG, PNG and TIFF.

The decoder travels with the picture

Darśana's container, sampuṭa (संपुट, a casket), carries the decoder inside the file next to the data. It decodes itself in an environment with no libraries and no network. Its contents are sealed, so a file whose bytes have changed is recognised before anything runs. A picture packaged this way carries everything needed to read it.

Svarūpa: camera raw to code to the identical picture

Svarūpa (स्वरूप) means one's own form. It is where Darśana is heading.

We are building toward a pipeline in which camera raw becomes a code, and the code becomes exactly the same picture, every sample. The proof is given on the SANSOS machine, a small RISC-V computer that counts every instruction it executes. The same 27,272-octet decoder does the work, and it fits comfortably inside the 88 KiB budget we set for it.

Agreement is the bar. The C99 twin, the normative Sassembly decoder running both natively and as WebAssembly, and the camera's own original data must all produce the same picture, with the same instruction count on both machines. The working set is drawn from openly licensed raw files: CC0 crops from raw.pixls.us (Phase One H 25, iPhone XS, Nikon D7000) and the R³ rain dataset (CC BY 4.0).

Beyond that we are designing two further directions: from words to picture, and from picture to motion. Both rest on the same foundation, that a picture is a program, and that a program can be run, counted and checked.

Why it matters

A photograph is evidence: of a scene, an experiment, a moment. Darśana treats it that way. The specification can be executed, the fast path is proven equal to it, the answer is identical on every architecture we run, and the file carries its own reader. Seeing, done exactly.
